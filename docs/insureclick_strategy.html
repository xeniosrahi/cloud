Root Cause Analysis: 6 Critical Issues

Identified bottlenecks preventing optimal performance

CRITICAL No Query Optimization ISSUE #1
Impact: 500-1000ms per request
Problem: Queries return entire Mongoose documents with overhead instead of lean() queries.

Example: Finding 100 lab tests returns full objects with methods, prototype chains, virtuals.

Why It Matters: Mongoose wraps each document, causing memory bloat and serialization overhead.
❌ BAD const docs = await LabTestModel.find({ labId }) // Returns 100 full Mongoose documents with overhead ✓ GOOD const docs = await LabTestModel .find({ labId }) .select('labTestName labTestCode mrp finalPrice') .lean() .limit(100) // Returns 100 plain JavaScript objects
CRITICAL No Response Compression ISSUE #2
Impact: 200-400ms on cellular networks
Problem: Large JSON payloads transferred uncompressed over network.

Example: Cart endpoint returns ~500KB uncompressed, ~50KB with gzip (90% reduction).

Why It Matters: Cellular networks benefit massively from compression due to bandwidth constraints.
❌ BAD - No compression const app = express() app.use(express.json({ limit: '2mb' })) ✓ GOOD - Enable gzip const compression = require('compression') app.use(compression({ level: 6, threshold: 1024 })) app.use(express.json({ limit: '2mb' }))
CRITICAL No Caching Strategy ISSUE #3
Impact: 800-1500ms per cacheable request
Problem: Every request hits MongoDB for static data (categories, tests, slots).

Statistics: 70% of requests are cacheable but hit DB every time.

Why It Matters: Lab tests, packages, slots don't change frequently but consume majority of DB queries.
❌ BAD - Always DB hit const tests = await LabTestModel.find({ labId }) // 1000 users = 1000 identical queries to MongoDB ✓ GOOD - Redis Cache const cached = await redis.get('labTests:' + labId) if (cached) return JSON.parse(cached) const tests = await LabTestModel.find({ labId }).lean() await redis.setex('labTests:' + labId, 3600, JSON.stringify(tests)) return tests
HIGH No Connection Pooling for External APIs ISSUE #4
Impact: 200-500ms per API call overhead
Problem: Partner API calls (Healthians, Redcliff) create new HTTP connections for each request.

Cost: TCP handshake + TLS negotiation overhead per slot fetch = 600-1200ms delays.

Why It Matters: Keep-alive connections reduce handshake overhead significantly.
❌ BAD - New connection per request const response = await axios.post(url, payload) ✓ GOOD - Keep-alive connection pool const httpAgent = new http.Agent({ keepAlive: true }) const httpsAgent = new https.Agent({ keepAlive: true }) const client = axios.create({ httpAgent, httpsAgent, timeout: 15000 }) const response = await client.post(url, payload)
HIGH Single-Threaded Express (No Clustering) ISSUE #5
Impact: 100-300ms queuing time per request
Problem: All requests processed on single CPU core, causing blocking and queuing.

Cost: Under load, slow requests block faster ones behind them.

Why It Matters: Node.js clustering enables multi-core utilization (4-8 worker processes).
✓ GOOD - Node Cluster const cluster = require('cluster') const os = require('os') if (cluster.isMaster) { const numWorkers = os.cpus().length for (let i = 0; i < numWorkers; i++) { cluster.fork() } } else { const app = require('./app') app.listen(3000) }
MEDIUM N+1 Queries & No Request Batching ISSUE #6
Impact: 2000-3500ms for mobile users
Problem: Frontend makes N separate requests for related data (cart → items → packages → tests).

Example: 5 sequential requests at 500ms each = 2500ms + network latency.

Why It Matters: Proper API design aggregates related data in single response.
❌ BAD - N+1 queries // Frontend makes 5 requests: GET /api/v1/cart GET /api/v1/cart/items GET /api/v1/cart/packages GET /api/v1/cart/tests GET /api/v1/cart/slots ✓ GOOD - Single aggregated endpoint GET /api/v1/cart?include=items,packages,tests,slots // Returns cart with all related data in one response

Create Redis Cache Service

File: src/services/cache.service.js

src/services/cache.service.js const redis = require('redis') const client = redis.createClient({ host: process.env.REDIS_HOST || 'localhost', port: process.env.REDIS_PORT || 6379, db: 0 }) client.connect() const DEFAULT_EXPIRY = 3600 // 1 hour async function getFromCache(key) { try { const value = await client.get(key) return value ? JSON.parse(value) : null } catch (e) { console.error('Cache get error:', e) return null } } async function setInCache(key, value, expiry = DEFAULT_EXPIRY) { try { await client.setEx(key, expiry, JSON.stringify(value)) return true } catch (e) { console.error('Cache set error:', e) return false } } async function deleteFromCache(key) { try { await client.del(key) return true } catch (e) { console.error('Cache delete error:', e) return false } } async function invalidatePattern(pattern) { try { const keys = await client.keys(pattern) if (keys.length > 0) { await client.del(keys) } return true } catch (e) { console.error('Cache invalidate error:', e) return false } } module.exports = { getFromCache, setInCache, deleteFromCache, invalidatePattern }
  • Impact: 800-1500ms reduction for cacheable requests
  • Effort: 20 minutes
  • Install: npm install redis

Enable Node.js Clustering

File: src/index.js

src/index.js const cluster = require('cluster') const os = require('os') const http = require('http') const numWorkers = process.env.NODE_WORKERS || os.cpus().length if (cluster.isMaster) { console.log(`Master process ${process.pid} starting ${numWorkers} workers...`) // Fork worker processes for (let i = 0; i < numWorkers; i++) { cluster.fork() } // Handle worker exit cluster.on('exit', (worker, code, signal) => { console.log(`Worker ${worker.process.pid} died (${signal || code}). Restarting...`) cluster.fork() // Auto-restart failed workers }) // Graceful shutdown process.on('SIGTERM', () => { console.log('SIGTERM received, shutting down gracefully...') for (const id in cluster.workers) { cluster.workers[id].kill() } process.exit(0) }) } else { // Worker process - start Express server const app = require('./app') const PORT = process.env.PORT || 3000 const server = http.createServer(app) server.listen(PORT, () => { console.log(`Worker ${process.pid} started on port ${PORT}`) }) // Graceful shutdown for worker process.on('SIGTERM', () => { console.log(`Worker ${process.pid} received SIGTERM, closing server...`) server.close(() => { process.exit(0) }) }) } // Verification: // ps aux | grep node // Should show 4-8 worker processes + 1 master
  • Impact: 100-300ms reduction in queuing, 8x throughput increase
  • Effort: 30 minutes
  • Recommended: 4-8 workers (= CPU cores)
